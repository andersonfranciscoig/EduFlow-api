# Project Development Guidelines


## General Rules
Understand the existing architecture before making changes.
Inspect only files directly related to the task.
Never scan the entire repository unless explicitly requested.
Follow existing coding conventions and design patterns.
Reuse existing services, utilities and components.
Do not introduce unnecessary dependencies.
## Backend
Respect the existing modular architecture.
Follow the existing controller, service and repository patterns.
Validate inputs and handle errors consistently.
Respect authentication and authorization rules.
Do not expose sensitive information.
Maintain backward compatibility unless requested otherwise.
## Implementation
Implement only the requested scope.
Avoid unrelated refactoring.
Do not duplicate existing functionality.
Do not modify database schemas without justification.
Run only relevant tests.
## Communication
Be concise.
Do not explain every file before implementation.
Report only important decisions.
Ask before making assumptions that affect architecture.
## Final Response
Summarize:
1. What was implemented.
2. Which files were modified.
3. Which tests were executed.
4. Any remaining issues.
